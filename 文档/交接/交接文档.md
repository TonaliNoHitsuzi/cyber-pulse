## 3. 固件关键参数与逻辑

### 3.1 信号链
```
压电膜 → ADC 1kHz DMA → 每5样本窗口(200Hz) min/max → dev=|极值-基线|
→ 阈值 40 + 最小间距 350ms 检峰 → 隔峰 i+2 → 中值(窗口9) → CV门 → 冷启动 → BPM
```

### 3.2 关键阈值
| 参数 | 值 | 说明 |
|---|---|---|
| 采样率 | 1000Hz | 10kHz 会激发 ADC 泵浦振荡 |
| 窗口 | 5 样本（200Hz） | |
| 峰阈值 | 40 | 可用 `thr` 命令改 |
| 最小峰间距 | 350ms | 可用 `gap` 改；跑步上限约 171 BPM |
| 基线 EMA | τ=4s + 跳变吸附(80/20样本) | |
| 质量门 | p50≥18 且 p95≥45（滞回 0..4） | 补发期间 p50 门槛 +12 |
| CV 门 | ≤0.12 | 拒绝噪声锁定 |
| 冷启动 | ≥5 间隔 且 连续 4 帧 | 首次出数约 3.5s |
| i+2 带宽 | 300~1400ms | |

### 3.3 BLE 协议
```
设备名: CYBER-PULSE
FFE0 服务
  FFE1 JSON   (Notify, 500ms): {"bpm":78,"bpm2":0,"sc":0.0,"state":"GOOD","p95":112,"p50":40,"q":1,"beat":1}
  FFE2 波形   (Notify, 100ms): int16 LE × 10（100Hz 原始 ADC）
  FFE3 补发   (Notify): [start_ms int32][n uint16][int16×n]，连接时自动补发 60s 缓存
  FFE4 命令   (Write): "C:thr 45" 等文本；或 4 字节 LE = 补发起点
```

### 3.4 命令通道（BLE 或串口）
| 命令 | 作用 |
|---|---|
| `?` | 打印配置 |
| `thr 42` / `gap 350` / `q 18 45` | 阈值/间距/质量门 |
| `dbg 0\|1` | UI/TRK 日志 |
| `dump 0\|1` | 帧缓冲回读（1KB/5s，最耗） |
| `mode 0\|1\|2` | 跟踪器：关/接管/影子 |
| `wave 0\|1` | 波形流开关 |
| `raw 0\|1` | R 行打印（200行/秒） |
| `save` | 存 NVS |

## 5. 今天的关键发现（务必记住）

1. **时基必须用采样序号，不能用处理时刻**——主循环卡顿会压缩时间戳
2. **"太稳定"是异常**——真实心率必有波动（σ≈0 要警惕）
3. **CV 门算在 i+2 上无效**——i+2 天然规整；要算在 i+1 或用其他判据
4. **蓝牙与悬空噪声无关**（开关 BLE 对照，p50 9 vs 6）
5. **跑步时心率 80-92**（自相关），步频 174-192，两者不同频但接近
6. **i+2 配对在高心率有 ±10% 偏差**（PLL/自相关才能救）
7. **串口监听会复位板子**（DTR/RTS 必须 open 前设 False）
8. **COM6 消失**用 `usbfix.ps1`（管理员删幽灵设备）

## 11. 血的教训（D6）

### 11.1 数据一回来立刻备份
- 手机导出后**先复制一份带时间戳的 .db 到电脑**，再做任何操作
- 本次因为没先备份，清理测试数据时把手机数据库写坏，今天的会话在 App 里丢失
- 现存的完整数据：`数据-2026-11-03.db`（电脑端存档）

### 11.2 绝不用 adb 直接写 SQLite
- `adb shell run-as ... sh -c 'cat > databases/x.db'` 会因换行转换损坏二进制
- 正确做法：**通过 App 自己的 API**（已加 `/session/delete?id=N`）或 UI 操作
- 若要整库恢复，需要 App 提供 `POST /restore` 接口，不要走 shell 重定向

### 11.3 串口读取必须设超时
- pyserial 默认 `timeout=None` 会永久阻塞；设备一旦静默，脚本就"卡死"
- 所有串口脚本必须 `s.timeout = 0.2`

### 11.4 设备静默后要能自恢复
- `rec open` 会关闭所有日志输出；若 PC 中途断开，设备会一直静默
- 已加 `rec wake` 复位命令，回显用 `puts` 而非 ESP_LOG（不受日志等级影响）

### 11.5 闪存分区带磨损均衡，不能直接当 FAT 读
- `esptool read_flash 0x110000` 得到的是 WL 层数据，不是标准 FAT
- 要原始导出的前提是：固件不用 wear_levelling 挂载（未实现）

THE ITERATION LOG

十个知识点，
其实是一条被数据推着走的路线

每一版算法都不是凭空想出来的：它先遇到一个具体的失败（多少拍、多少 BPM、多少秒），再从数据或生理特征里找到一个线索，做出一个最小改动，然后看结果、留下新的问题。下面按“问题 → 线索 → 改动 → 结果 → 为什么还要升级”把整条链摊开。看完全程，再回头看任何一个动画，会知道它到底在补哪个洞。

先记住这个
工作模型

容积传导 + 多路径叠加：心脏的震动沿血管、肌肉、骨骼传到同一个接触点，速度有快有慢、衰减有大有小。血管这条路最快、衰减小，先到并构成主峰；其他路径晚到、弱，叠成尾巴/底噪。按压力度改变的正是这条主路径的信噪比：太松耦合不足，太紧把主路径压扁、底噪还在。

版本轨：V0 是失败起点，之后每一版都只补上一版的洞
V0包络状态机→ V1峰普查→ V1.1隔峰配对→ V1.2质量门→ V1.3输出端门控→ V2状态机→ V3卡尔曼→ V4动态配对→ V5模板 NCC→ V6贝叶斯
V0
起点包络状态机

先承认：老算法在真实波形上一拍都出不来

0 拍 → 82 峰

这是整条路线的起点，也是最反直觉的一步：不是“调参”，而是发现旧算法假设错了。

面对的问题

旧状态机等“波形回到基线”再算下一拍，但真实脉搏每拍有两个鼓包，它永远等不到，整段输出 0 拍

数据/领域给的线索

人工看同一段数据明明有脉搏；回放历史数据，发现旧引擎一直卡在“等基线”状态。问题不在传感器，在“拍”的定义。

这次改动

放弃“回到基线”的假设，改成峰普查：超过阈值 40 就算候选峰，两个峰至少隔 350 ms。

结果

同一份数据 0 拍 → 82 峰；所有历史“废数据”重放后信号都在。

为什么还要升级

峰是有了，但一拍有两个鼓包 —— 每个都数，心率会翻倍。

进 01 →
V1
升级自V0 峰普查

“跳一个峰”：先把一拍认对，再谈心率

167 → 83 BPM

这不是拍脑袋的规则，先有一个判决实验；后来又回看了一次：双峰到底是机械余震、生理信号，还是测量方式带进来的两个源？

面对的问题

见到峰就配对，得到 167 BPM，而真人只有 80 出头 —— 一拍被数成了两拍。

数据/领域给的线索

双峰间距约 360 ms。加质量后间距只从 360 → 365 ms，几乎不动 → 不是板子余震。但后来回看：早期“右拇指按左腕”的测法会同时接触两个身体，双峰其实是第二路信号，不能直接当成重搏波。

这次改动

跳过一个峰，用第 i 个和第 i+2 个配对；中值抗单次抖动。第一路配第一路、第二路配第二路。

结果

725 ms → 83 BPM，与同刻手表 80–82 吻合。

为什么还要升级

跑到 150 BPM 时两路信号挤在一起，“隔一个”实际跨了两拍（800 ms），输出 75（半值）。

进 02 →
V1.2
升级自V1.1 隔峰

质量门：先证明“这段有脉搏”，再允许出数

118 s → 0 s

隔峰解决了“数错”，但没解决“没东西可数”。悬空薄膜给了最刺眼的反例。

面对的问题

悬空 120 秒，118 秒都在输出约 67 BPM。屏幕上很“稳定”，但根本没贴人。

数据/领域给的线索

悬空 p50 只有 12、p95 约 35；贴肤 p50 42–62、p95 114–221。噪声尖峰能凑出 500–1400 ms 的“合法间隔”，但主路径强度/信噪比很低。

这次改动

同时看“最猛 5%”（p95）和“大多数时候”（p50），本质是在要求信噪比：p95≥45 且 p50≥18 才放行。

结果

假读数 118 s → 0 s；贴肤好信号复算不受影响。

为什么还要升级

第一版把门加在峰值检测里，一弱就丢峰，隔峰配对断链，BPM 变空或算出 56。

进 03 →
V1.3
升级自V1.2 质量门

门装错位置：把好信号也弄坏了

76–78 · σ=0.7

这是最典型的一次“修复引入新 bug”，也是全项目最重要的工程教训之一。

面对的问题

加了质量门后，BPM 变空、掉到 56、中途掉零。门越严，坏得越明显。

数据/领域给的线索

门在峰值检测里：信号短暂变弱就丢峰 → 隔峰配对错位 → 算出的不是“没数据”，而是“错数据”。

这次改动

检测保持自由，只在输出端门控；中值窗口 7→9；与中值偏差 >30% 的间隔不入窗。

结果

稳定按压 76–78 BPM、σ=0.7，中途掉零 0 次。

为什么还要升级

数值稳了，但 GOOD/WEAK 状态在门槛附近来回跳，用户看不懂“现在能不能信”。

进 03 →
V2
升级自V1.3 输出端门控

状态机：把“能不能信”也变成一个算法输出

GOOD 91–100%

数值不是唯一输出。对一个非专业用户，“现在这个数能不能信”同样重要。

面对的问题

GOOD/WEAK 反复跳；有时屏幕有数，但其实是悬空或过压。

数据/领域给的线索

p95 在门槛 52 附近徘徊；状态没有平滑，也没有“质量优先”的优先级。

这次改动

五状态 + 质量优先 + p95 平滑（τ≈2s）+ 0–4 滞回；测不了时显示 SRCH/---。

结果

GOOD 占比 91–100%；悬空 0 误报；松手 <1 s 归零。

为什么还要升级

静息稳了，但跑步时 9 拍中值滞后 3–5 秒，加速段还会被 ±30% 过滤拒掉。

进 04 →
V3
升级自V2 状态机

卡尔曼：把“心率正在变快”也放进模型

120 → 83

中值只看过去 9 个数，像后视镜；卡尔曼多了一个速度状态，敢往前看。

面对的问题

9 拍中值在 150 BPM 横跨约 3–5 秒；快速爬升时 ±30% 过滤会连续拒绝，最后清窗断档。

数据/领域给的线索

心率是慢变量，但确实有“变化速度”；间隔计时误差（σt≈20ms）也可以建模成测量噪声。

这次改动

状态 [hr, v] 匀速模型；先预测、再用测量修正；R 由计时误差推出，不再手调。

结果

初值故意给 120，第一拍拉回 83；仿真加速段 MAE 2.4–6.8（指数/冲刺/正弦）。

为什么还要升级

滤波器再好，也救不了“配对” —— 高心率时 i+2 仍然跨两拍，输出 75。

进 05 →
V4
升级自V3 卡尔曼

动态配对：用“当前周期”决定谁是第二路信号

150 → 150

终于回到根因：不是滤波不够好，是“哪两个峰该配对”这件事本身随心率在变。

面对的问题

150 BPM 时两路信号挤在一起，i+2 跨了整整两拍（800 ms），稳态输出 75。

数据/领域给的线索

周期 P=60000/hr 已知；第二峰在 0.55P 内，漏拍在 1.8P 外。用当前 P 就能判断“这个峰是第二路信号还是下一拍”。

这次改动

用 P_est 动态判定第二峰/漏拍；搜索窗口由协方差（含速度）导出；加 45 BPM/拍的绝对伪迹门。

结果

仿真 150→150；冲刺循环 MAE 6.8；结构正确性得到验证。

为什么还要升级

启动锁定仍不稳；阶跃下降 MAE 60.4（恢复慢）。而且“哪一个峰”仍有歧义。

进 06 →
V5
升级自V4 动态配对

模板 NCC：从“像不像一个尖”升级到“像不像一次心搏”

真拍保留≈100%

峰检测本质也是模板匹配，只是模板只有一个尖。把它换成整段形态，就能否决“半段波形”。

面对的问题

峰太多：纹波、噪声、第二峰都在抢“这一拍”。只靠幅度和时序，总会误选。

数据/领域给的线索

一段完整脉搏波形有形态（主峰 + 第二峰 + 拖尾）；伪峰只有局部尖，没有整段形状。

这次改动

心搏模板 NCC：粗筛出候选峰，再用整周期形态打分；NCC>0.8 才更新模板。

结果

伪峰被拒，真拍保留率≈100%；原型 NCC 最高 0.78。

为什么还要升级

形态对了，配对还是 i+2 —— 150 BPM 时依然跨两拍，输出 75。三层缺一不可。

进 06 →
V6
升级自V5 模板 NCC

贝叶斯：把“信谁、信多少”变成可计算的东西

后验 751 ± 17 ms

不是二选一，也不是拍脑袋加权，而是让三路证据相乘，谁更确定谁的话语权更大。

面对的问题

单一探测器会失效（幅度低/形态差）；固定 R 难调；需要“任一路失效还能降级”。

数据/领域给的线索

幅度强在时域锐度，形态强在积分类信噪比，两者互补；后验曲率还能直接给出测量不确定度。

这次改动

先验（KF 预测）× 幅度似然 × 形态似然 → 后验 argmax；R 由后验曲率自动得出。

结果

后验 751 ± 17 ms；一路失效可降级；两路都弱则本拍不出数。

为什么还没上线

Python 原型 NCC 最高 0.78，但检测器接口有 bug（返回 0 个峰），尚无召回/精确率；仍保持 USE_TRACKER=0 影子模式。

进 07 →
H1
并行工程线机构

算法之外：软背衬会把信号“吃掉”

−8.4 BPM

同一套算法，换一块棉花垫，结果就崩。问题不在代码，在力的传递。

面对的问题

棉花背衬下 p95 ≤50，同刻对照误差 −8.4 BPM；松表带也不可靠。

数据/领域给的线索

膜靠传导来的微小振动变形；软材料吸振，主路径信号变弱、信噪比下降。刚性板能把振动能量“兜”到膜上。

这次改动

膜–刚性板–绑带三明治；绑带压“板”不压“膜”；让振动传到膜，而不是被软垫吸走。

结果

刚性板 p95 154，棉花 ≤50；背衬刚度定律写进规范。

遗留

手套装配、长期佩戴（汗液/皮肤适应）未测；拇指被动贴装待验证。

进 09 →
H2
并行工程线数据链

数据链：断线不能等于丢数据

79 条 / 36.9 s / 无断档

算法再准，数据没送到手机也白搭。断线在可穿戴里是常态，不是异常。

面对的问题

BLE 断线就丢波形；手机端也无法理解板子的内部算法。

数据/领域给的线索

脉搏能量 <10 Hz，1 kHz 抽成 100 Hz 仍能画形态；断线时板子仍在采样。

这次改动

FFE1–4 四个特征 + 60 s 环形缓存 + FFE4 请求/FFE3 补发。

结果

端到端 79 条 / 36.9 s / 平均 512 ms / 无断档；CSV+manifest 正常。

遗留

长时跑步录制、功耗、断线 60 s 以上的策略待定。

进 08 →
H3
并行工程线验证

验证：先保证“比的是同一件事”

±2 BPM

顺序测量差出 82 vs 68，不是精度差，是实验设计错了。同刻对照之后，误差才可谈。

面对的问题

先测本机、再测手表，得到 82 vs 68；整轮平均还被弱耦合段拖到 −9.4 BPM。

数据/领域给的线索

按压会升压、放松会回落，两次不是同一生理状态；一轮里好段/坏段混杂。

这次改动

同刻对照；按 p95/状态分段，只统计好段；弱档直接拒绝出数。

结果

跨 2 人/多位置 ±2 BPM（最好 −0.2）；同一轮 −9.4 → −0.2。

遗留

跑步段仍需现场同刻对照；测试机会稀缺，先用节拍器阶梯等效验证。

进 12 看其他边界 →

主线：每一层只解决上一层的失败

  1. 先定义“一拍”：从“等基线”改成峰普查；再用隔峰配对，把一次心跳的两个鼓包认成一次。
  2. 再定义“能不能信”：质量门只装在输出端；状态机把“没贴/太弱/太紧/正常”分开。
  3. 然后让“时间”跟上变化：卡尔曼加速度状态；动态配对按当前周期决定谁是第二路信号。
  4. 最后让“形态”和“证据”进来：模板 NCC 否决半段波形；贝叶斯把幅度与形态相乘，并自动给出 R。
  5. 工程侧并行：机构保证力传到膜；数据链保证断线不丢；同刻对照保证比的是同一件事。
  6. 最后守边界：时基、CV、冷启动、数据新鲜度、采集链路；不加新方法，也能让结果更可信。

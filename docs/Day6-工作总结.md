## 三、固件更新

### 3.1 闪存采集模式（核心）

```
分区：nvs 24K | phy 4K | app 1M | storage 3M (FAT)
文件：/storage/recNNN.raw
格式：16B 文件头("CPLS", ver, fs, 起始毫秒)
      + 每块 [uint32 板载毫秒][uint16 n][int16 × n]（n=1000，即 1 秒）
速率：2006 字节/秒 → 3MB 可存 26 分钟
```

**实测**：181 秒记录成功；**实际采样率 984 Hz**（比标称 1000 低 1.6%，时间戳可校正）。

### 3.2 回传协议

- 逐块请求：`rec open N` → `rec rd <seq>` ×N → `rec close`
- 每块 512B + 序号 + CRC16，PC 端校验后重传
- 回传期间全程静默（`g_quiet`），防止日志混入二进制流

### 3.3 其他
- `pair 1|2`：隔峰配对（2=上限 86，1=上限 171）
- 运动判定（纯压电占空比）：实测按压会误判，默认关闭
- 显示保持：短暂失锁沿用上次值 ≤3s，BPM 标签显示 `~`
- OLED 初始化提前到 BLE 之前（开机亮屏 1.5s → 0.3s）
- 蜂鸣器标定代码已彻底移除

## 五、事故与教训（已写入交接文档 §11）

**事故**：清理测试数据时用 `adb shell >` 回写数据库，换行转换损坏二进制，Room 重建空库 → 手机上今天的会话丢失。

**数据没丢**：电脑端已存档 `数据-2026-11-03.db`（2.2MB，会话 9-14 完整）。

**五条教训**：
1. 数据一回来先备份（带时间戳的副本）
2. 绝不用 adb 直接写 SQLite，只能走 App 自己的接口
3. 串口脚本必须设 `timeout`（默认 None 会永久阻塞）
4. 设备静默后要能复位（已加 `rec wake`）
5. 闪存分区带磨损均衡，不能直接当 FAT 读

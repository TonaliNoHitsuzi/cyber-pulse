# 交接任务：把测量记录关联到公开天气数据

> 目标：给每条测量记录补上**当时的实际天气**，供后续分析（温度/湿度对脉搏传导、运动表现的影响）。
> 任务独立、无需硬件、只用 Python，适合一人单独完成。

---

## 一、背景

我们的设备（ESP32-C3 + 压电薄膜）在手套上测脉搏，App 会记录每组的元数据。目前温湿度是**手填**的，不准确。
现在 App 已经会自动采集 **GPS 坐标**，可以据此反查当时当地的真实天气。

---

## 二、输入数据长什么样

每组测量导出后是一个目录，含：

```
<会话目录>/
  samples.csv      # 逐拍/逐通道样本（含 GPS_SPEED 行）
  manifest.json    # 会话元信息（姓名/学号/运动类型/开始时间等）
```

### samples.csv 的结构

关键字段：`session_id, student_id, gender, hand, finger, temperature, humidity, class_id,
channel, channel_label, unit, ts_ms, ts_iso8601_utc, value, source, quality, extra`

其中 `channel = "GPS_SPEED"` 的行，`extra` 字段是一个 JSON 字符串，形如：

```json
{"lat":31.2345,"lon":121.4737,"acc":8.5}
```

- `lat/lon`：当时位置（WGS84 十进制度）
- `acc`：GPS 水平精度（米），越大越不可靠

**注意**：一组测量会有多条 GPS_SPEED（每 3 秒一条）。取 **`acc` 最小的那条**作为该组的位置参考（不一定取第一条）。

### manifest.json 里需要的字段

```json
{
  "created_at_ms": 1793603937743,   // 会话创建时间（毫秒时间戳，UTC）
  "started_at_ms": 1793603938000,
  "ended_at_ms": 1793604123000
}
```

---

## 三、要做什么

写一个脚本 `weather_join.py`：

1. 输入：一个会话目录（或整个导出目录的父目录，批量处理）
2. 从 `samples.csv` 提取 `GPS_SPEED` 行，选 `acc` 最小的一条 → 得 `lat, lon`
   - 若整组没有 GPS 数据 → 输出 `weather_source = "no_gps"`，跳过
3. 用 `manifest.json` 的 `started_at_ms / ended_at_ms` 换算成
   - 日期（本地时间，Asia/Shanghai）
   - 起始小时、结束小时（四舍五入到整点）
4. 调 Open-Meteo 历史接口（**免 API key**）：

```
https://archive-api.open-meteo.com/v1/archive
  ?latitude={lat}&longitude={lon}
  &start_date={YYYY-MM-DD}&end_date={YYYY-MM-DD}
  &hourly=temperature_2m,relative_humidity_2m,precipitation,weather_code,wind_speed_10m
  &timezone=Asia%2FShanghai
```

5. 取覆盖 `[起始小时, 结束小时]` 的逐小时数据，**对区间求平均**（天气代码取众数）
6. 把结果写进会话目录下的 `weather.json`，并把同样的字段追加到 `manifest.json`：

```json
{
  "weather_source": "open-meteo",
  "weather_lat": 31.2345,
  "weather_lon": 121.4737,
  "weather_accuracy_m": 8.5,
  "weather_time_range": "2026-11-02T15:00 ~ 2026-11-02T15:30",
  "temperature_c": 21.4,
  "humidity_pct": 63.0,
  "precipitation_mm": 0.0,
  "weather_code": 3,
  "weather_text": "阴",
  "wind_kmh": 11.2
}
```

7. 同时生成一个汇总表 `weather_summary.csv`（每行一组会话），方便直接拿去和心率数据 merge。

### WMO 天气代码 → 中文

| code | 含义 | code | 含义 |
|---|---|---|---|
| 0 | 晴 | 61/63/65 | 小/中/大雨 |
| 1/2/3 | 少云/多云/阴 | 71/73/75 | 雪 |
| 45/48 | 雾 | 80/81/82 | 阵雨 |
| 51/53/55 | 毛毛雨 | 95/96/99 | 雷暴 |

---

## 四、验收标准

1. 跑一遍 `python weather_join.py <某个会话目录>`，能生成 `weather.json` 且字段齐全
2. 挑一组已知时间地点的记录，人工核对温度是否合理（±3℃ 内）
3. 对没有 GPS 的旧数据，脚本应正常跳过并注明 `no_gps`，不报错
4. 支持批量：`python weather_join.py <导出根目录>` 遍历所有子目录

---

## 五、注意事项

- **GPS 精度对天气完全够用**：天气网格是 1~11 km，哪怕 100m 误差也几乎不影响取到同一格点。开阔地 ±3~5m，城市 ±10~30m。
- **Open-Meteo 免费、无需注册**；历史数据是 ERA5 再分析（约 5 天延迟，实测当天的数据隔天可取）
- **时区统一用 Asia/Shanghai**，否则跨零点会取错日期
- GPS 在室内常常没有定位 → 允许组员**手动补一个位置**：在会话目录放一个 `location_manual.json`（`{"lat":..,"lon":..}`），脚本优先用它
- 别把整条 GPS 轨迹写进 weather.json，只存选中的那一个点和精度即可

## 六、可选加分项（有余力再做）

- 用 `current` 接口（`https://api.open-meteo.com/v1/forecast?...&current=...`）处理**当天刚测完**的情况（历史库有延迟）
- 加气压（`surface_pressure`）作为环境参考，但**不要用来算海拔**（手机气压计绝对精度 ±10~50m，无意义）
- 把 `weather_summary.csv` 和 `manifest.json` 的时间戳对齐到会话开始时刻，方便与 `ui_frames` 做时间序列 join

# 课堂演示网页 · 串口对接文档

> 给做展示网页的对话用。目标：**实时读取设备串口 → 网页画波形/心率；手机摄像头画面同时展示**。

---

## 1. 硬件与串口参数

| 项 | 值 |
|---|---|
| 端口 | `COM6`（拔插后可能变，先枚举） |
| 波特率 | **115200**（USB-CDC，实际速率约 9~11 KB/s） |
| 数据位/校验/停止 | 8N1 |
| 设备名 | CYBER-PULSE（BLE 名） |

### ⚠️ 打开串口的唯一正确姿势

芯片是 USB-Serial-JTAG，**DTR/RTS 必须在 open 之前置 False**，否则每次连接都会复位板子：

```python
import serial
s = serial.Serial()
s.port = 'COM6'
s.baudrate = 115200
s.dtr = False
s.rts = False
s.timeout = 0.2          # 必须设，否则设备静默时会永久阻塞
s.open()
```

## 2. 串口输出的四类行

所有行以 `\n` 结尾（ESP_LOG 行是 `\r\n`）。按前缀区分：

### 2.1 `R,` —— 波形（演示主力）

```
R,<seq>,<min>,<max>
例: R,12034,1867,1881
```

| 字段 | 含义 |
|---|---|
| seq | 采样序号，每 5ms +1（即 **200 行/秒**） |
| min/max | 这 5ms 内 ADC 的最小/最大值（0~4095） |

- 速率：200 行/秒，约 4 KB/s
- 画图建议：`y = (min+max)/2`，或画 min/max 两条线（更有"脉搏"观感）
- **时间轴**：`t = seq * 5 ms`（这是最可靠的时基，不要用到达时间）

### 2.2 `UI|` —— 算法状态（心率/状态）

```
UI|bpm=83 cv=0.045 conn=3 state=GOOD p95=88 p50=39 q=1 beat=0 flush=0 duty=0.12
```

| 字段 | 含义 |
|---|---|
| bpm | 心率（**0 = 未出数**；运动中恒为 0） |
| state | `GOOD`/`WEAK`/`IDLE`/`VIB`/`OVER`/`SRCH` |
| p95/p50 | 信号幅度（p95 越大耦合越好，正常 45~200） |
| q | 质量位（1=可用） |
| beat | 本帧是否有搏动（驱动"心跳灯"用） |

- 速率：**2 行/秒**
- 需要 `dbg 1` 才输出

### 2.3 `TRK|` —— 影子跟踪器调试（演示不用）

```
TRK|old=0 new=0 sc=0.20 R=0 sa=0.0 cost=16500us heap=138000
```
需要 `dbg 1`，建议关闭：`dbg 0`。

### 2.4 `FB0|` / `FB1|` —— OLED 显存回读（演示必关）

每 5 秒打印 128×32 点阵 + CRC，约 1KB。演示时**必须关闭**，否则串口会被淹没：

```
dump 0
```

## 3. 演示模式的一键配置

```
raw 1      开启 R 行（波形）
dbg 1      开启 UI| 行（心率状态）
dump 0     关闭显存回读
wave 1     保持波形 BLE 推送（不影响串口）
```

发完可 `save` 写入 NVS，下次上电自动生效。

**恢复安静模式**（做数据实验时）：
```
raw 0
dbg 0
dump 0
save
```

## 4. 命令速查（全部以 `\n` 结尾发送）

| 命令 | 作用 |
|---|---|
| `?` | 打印当前配置 |
| `raw 0\|1` | R 行开关 |
| `dbg 0\|1` | UI/TRK 行开关 |
| `dump 0\|1` | 显存回读开关 |
| `wave 0\|1` | BLE 波形推送开关 |
| `thr 40` / `gap 350` | 峰阈值 / 不应期 |
| `q 18 45` | 质量门（p50/p95） |
| `cons 0..100` | 保守度 |
| `mfilter 0\|1` | 运动门控（默认 0） |
| `motion 0\|1` | 运动判定（默认 0，按压会误判） |
| `pair 1\|2` | 隔峰配对（2=上限 86，1=上限 171） |
| `led 0..100` / `fx 0..7` | 灯带亮度 / 灯效 |
| `save` | 写 NVS |
| `rec start/stop/list/erase` | 闪存采集 |

## 5. Python 读取骨架

```python
import serial, re, threading

s = serial.Serial()
s.port = 'COM6'; s.baudrate = 115200
s.dtr = False; s.rts = False; s.timeout = 0.2
s.open()

wave = []          # [(seq, min, max), ...]  最多保留 500 点
last_ui = {}

def reader():
    while True:
        line = s.readline().decode('utf-8', 'replace').strip()
        if line.startswith('R,'):
            _, seq, lo, hi = line.split(',')
            wave.append((int(seq), int(lo), int(hi)))
            if len(wave) > 500: wave.pop(0)
        elif line.startswith('UI|'):
            for kv in line[3:].split(' '):
                if '=' in kv:
                    k, v = kv.split('=', 1); last_ui[k] = v

threading.Thread(target=reader, daemon=True).start()
```

**前端推送**：用 WebSocket 每 50ms 推一次 `{"wave":[...], "bpm":83, "state":"GOOD"}`。

## 6. BLE 备选（不插线时）

| 特征 | 内容 |
|---|---|
| FFE1 (Notify) | JSON，500ms：`{"bpm","bpm2","sc","state","p95","p50","q","beat","t"}` |
| FFE2 (Notify) | 波形 int16×10，100ms（100Hz）|
| FFE4 (Write) | `C:<命令>` 文本，和串口命令一致 |

浏览器可用 **Web Bluetooth**（Chrome/Edge，需 HTTPS 或 localhost）。

## 7. 手机摄像头接入

我们没有现成的视频接口，三个可行方案：

| 方案 | 做法 | 优点 |
|---|---|---|
| **A（推荐）** | 手机装「IP Webcam」类 App，局域网取 MJPEG 流，网页 `<img src="http://手机IP:8080/video">` | 无需改像素，画中画效果最好 |
| B | 手机用 USB 当摄像头（Windows 相机 App / DroidCam），网页用 `getUserMedia` 选该设备 | 有线稳定 |
| C | 直接用笔记本摄像头对着手 | 最简单，但拍不到特写 |

## 9. 坑位清单

1. **DTR/RTS 在 open 之前设 False** —— 否则每次连接都复位板子
2. **必须设 `timeout`** —— 默认 None 会永久阻塞
3. **演示前 `dump 0`** —— 否则每 5 秒 1KB 点阵图淹没串口
4. **`g_quiet` 可能被残留为 1**（上次回传中断导致）——此时所有输出消失，发 `rec wake` 复位
5. **COM 端口号会变** —— 拔插后重新枚举，别写死
6. **`bpm=0` 是正常的** —— 未出数或判定为运动中
7. **R 行没有时间戳** —— 用 `seq × 5ms` 换算，别用到达时间

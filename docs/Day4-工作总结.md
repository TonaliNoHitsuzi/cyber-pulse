## 一、今天最重要的三个结论

### 1. "78 BPM 恒定"是**时间戳压缩**造成的，已修
- 主循环每 500ms 有 15ms 的模板匹配 + 每 5 秒 1KB 的调试打印，导致滞后 **217ms**
- 卡顿期间 ADC 持续采样堆积，恢复处理时**所有窗口的时间戳几乎相同** → 间隔被压缩 → BPM 失真
- **修复**：时基改用**采样序号**（`seq × 5ms`），ADC 1kHz 恒速，序号就是完美时钟，彻底免疫卡顿
- **效果**：输出从恒 78 变为 72~84 自然波动，CV 从 0.17 降到 0.09

### 2. 悬空假阳性是**不应期锁定**，已加 CV 门
- 信号弱时噪声峰在 350ms 不应期一到就被记为峰 → 间隔 ≈ 不应期 → BPM = 60000/(2×365) ≈ 82 → 稳定 78
- **判别**：真实脉搏间隔 CV ≤ 0.05；噪声锁定 CV > 0.15
- **修复**：CV > 0.12 不出数 + 冷启动保护（≥5 个间隔且连续 2 秒通过才输出）
- **验证**：同刻对照两次，误差 **0~1 BPM**

### 3. 跑步数据：心率约 80-92，不是伪迹
- 两组慢跑（赵、张，共 295 秒波形）
- 原始波形自相关（1-4Hz）：**赵 80 BPM、张 89.6 BPM**
- IMU 步频：174 spm / 192 spm（与心率不同频）
- **步态耦合不成立**（互相关 r ≈ 0.2）
- 设备显示 78/82，偏差来自 i+2 配对的系统性误差（±10%）

## 二、App 产品化（v2.0.0）

### 状态机改为单线流程
```
首页 →「开始新测量」→ 表单 → 连接页（显式「进入测量」）
     →「开始测量」→ 3-2-1 倒计时 → 测量 → 退出即结束落档
```

### 关键改动
| 项 | 内容 |
|---|---|
| 连接层 | 连上后显示「进入测量」按钮，不再自动跳 |
| 测量层 | 开始按钮 + 3 秒倒计时；退出/返回自动结束 |
| 并发控制 | 不允许同时两组；启动时收尾残留会话 |
| 跨厂商 | 前台服务（常驻通知）防系统冻结 |
| 权限 | 进入 App 一次性批量申请（蓝牙/定位/活动识别/通知） |

### 新增采集通道
| 通道 | 频率 | 用途 |
|---|---|---|
| GPS_SPEED（含经纬度/精度）| 3s | 强度真值 + 天气关联 |
| ORIENT | 2s | 口袋/手持判定 |
| RSSI | 5s | 链路质量 |
| STEP / STEP_TOTAL | 事件 | 系统硬件计步器 |

去掉：气压/海拔（精度 ±10~50m，平地无意义）、环境光。

## 三、固件改进

| 改动 | 说明 |
|---|---|
| **时基改采样序号** | 根治时间戳压缩 |
| **CV 规律性门** | 拒绝噪声锁定的伪 BPM |
| **冷启动保护** | 至少 5 个间隔 + 连续 2 秒 |
| **补发期质量门收紧** | p50 门槛 18→30（补发射频抬底噪）|
| **串口命令通道** | `thr/gap/q/dbg/dump/mode/wave/raw/save/?` |
| **wave/raw 开关** | 现场可关波形流与 R 行打印，降负载 |
| **NVS 持久化** | 配置掉电保持 |

## 四、今天修掉的 7 个 bug

1. **时间戳压缩**（主因）→ 采样序号时基
2. **不应期锁定假阳性** → CV 门 + 冷启动
3. **补发期间误判断链**（`lastDataTs` 未在补发回调更新）→ 连上 1.6 秒被判死
4. **结束会话执行两次**（BackHandler + onDispose）→ 加防重标志
5. **权限请求被吞**（连发多个单请求）→ 批量申请
6. **GPS 只有 GPS_PROVIDER**（室内无信号）→ GPS+NETWORK+PASSIVE 三源
7. **IMU 时间戳全相同**（循环内用了同一个 now）→ 每样本独立 dt

## 五、工程环境问题（两个非代码故障）

| 问题 | 根因 | 解法 |
|---|---|---|
| COM6 消失，拔插/RST 无效 | Windows 把板子 USB 复合设备标记为失效实例 | 管理员 `pnputil /remove-device` 删幽灵设备（脚本 `usbfix.ps1`）|
| 串口一开板子就重启 | pyserial 默认拉 DTR/RTS | `open()` 前先设 `dtr=False; rts=False` |

## 八、关键教训

1. **"太稳定"本身就是异常信号**——真实生理量必有波动
2. **算法参数会伪装成测量结果**——输出恰等于参数倒数时必须怀疑
3. **控制变量做实验**（BLE 开关对照证明射频无关）
4. **先看事实再看推理**——帧缓冲回读、原始波形频谱比臆测可靠
5. 用户的一次直觉质疑，抵得上十次自动化测试
